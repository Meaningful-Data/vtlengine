:Tests: ``aggregate avg`` at ``(DS_1 + DS_2) + DS_3``: two operators, so ``At_1`` follows their order of execution.
:Manual: `define viral propagation <https://sdmx-twg.github.io/vtl/v2.2/reference_manual/vtl_dl_rulesets/viral_attributes.html>`__: "avg is not associative, because an average does not record how many values it summarises", and "Across the operators of an expression, the propagation follows their order of execution (precedence, associativity and parentheses), so the result depends on how the operations are grouped", as the page shows on ``(DS_1 + DS_2) + DS_3``. This is the clarification that #1175 asked for (sdmx-twg/vtl#744).
:Expected: ``At_1`` avg(avg(1, 2), 6) = 3.75 and avg(avg(6, 2), 1) = 2.5, where the whole set would give 3; ``Me_1`` 111 and 222. The User Manual agrees: the propagation "is performed always in the same order of execution of the Operators of the expression".
