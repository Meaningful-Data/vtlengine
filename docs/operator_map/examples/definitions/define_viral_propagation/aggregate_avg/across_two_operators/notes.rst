:Tests: ``aggregate avg`` at ``(DS_1 + DS_2) + DS_3``: two operators, so ``At_1`` follows their order of execution.
:Manual: `define viral propagation <https://sdmx-twg.github.io/vtl/v2.2/reference_manual/vtl_dl_rulesets/viral_attributes.html>`__: the rule "is applied recursively to the values pair by pair. The final result is independent of the order in which the pairs are evaluated", while an aggregate "must collapse the set of operand values to a single result": for ``avg`` the two differ.
:Expected: ``At_1`` avg(avg(1, 2), 6) = 3.75 and avg(avg(6, 2), 1) = 2.5, where the whole set would give 3; ``Me_1`` 111 and 222. The User Manual agrees: the propagation "is performed always in the same order of execution of the Operators of the expression".
:Team decision: 📌 #1175, closed on 2026-10-22: the standard "will be clarified that the avg relies on the execution order" (sdmx-twg/vtl#744). Within one operator ``avg`` takes the whole set of operand values; across operators the propagation follows the order of execution.
