:Tests: ``case when DS_1 > 20 then DS_2 when DS_1 > 10 then DS_3 else DS_1``: two overlapping conditions written inline, on data sets, to see which true condition wins.
:Manual: `Case <https://sdmx-twg.github.io/vtl/v2.2/reference_manual/operators/Conditional%20operators/Case/index.html>`__: at data set level the operator "returns the Data Point from the *thenOperand* when the first Data Point of *condition* having the same Identifiers’ values evaluates to **true**; returns the Data Point from *elseOperand* if none of the **when** conditions evaluates to **true**".
:Expected: (1, 5), (2, 2) and (3, 300): id 1 meets no condition, so it keeps ``DS_1``; id 2 meets only the second, so it comes from ``DS_3``; id 3 meets both, and the first wins, so ``DS_2``'s 300, not ``DS_3``'s 3. No recorded team decision applies, so the expected output follows the manual's "first".
:Finding: pandas returns 3 for id 3: the last true condition wins ("last-match-wins" in the comment of ``visit_Case`` in the DuckDB transpiler); DuckDB crashes with a ``ParserException`` on the inline condition, so the engines differ.
