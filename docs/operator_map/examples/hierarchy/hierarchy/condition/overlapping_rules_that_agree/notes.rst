:Tests: two rules for ``A``, ``when Id_1 <= 2 then A = B + C`` and ``when Id_1 >= 2 then A = B + C``, whose conditions overlap at ``Id_1`` 2: both compute (2, A) there, with the same value.
:Manual: `define hierarchical ruleset <https://sdmx-twg.github.io/vtl/v2.2/reference_manual/vtl_dl_rulesets/hierarchical_rulesets.html>`__: "if a left Code Item is calculated by means of more Rules [...], there is the risk of producing erroneous results (e.g., duplicated data)"; the manual does not say what the result is.
:Expected: with the defaults ``non_null``, ``rule`` and ``computed``, (1, A, 3) from the first rule alone, and (2, A, 30) once, as both rules compute 10 + 20 = 30.
:Team decision: `#1193 <https://github.com/Meaningful-Data/vtlengine/issues/1193>`__ chose option 3, "When every rule that applies to a data point computes the same value, return that data point once", "as it follows the logic used already in older versions of the engine and it is the least prone to errors". `#1210 <https://github.com/Meaningful-Data/vtlengine/pull/1210>`__ did it on both engines, comparing the measure and the viral attributes, and keeps 2-1-10-1 for rules that compute different values.
