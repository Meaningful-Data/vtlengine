# left_join: aggr_group_all

Authored. The `aggr` clause sums `Me_1` with the deprecated `group all time_agg("A")`, which groups the quarters by year.

Manual page: [Left Join](https://sdmx-twg.github.io/vtl/v2.2/reference_manual/operators/Join%20operators/Left%20Join/index.html).

Inputs (own pair: `group all` needs a time identifier): `DS_1` and `DS_2` have the identifier
`Id_1` (Time_Period, quarters) and one Number measure each. The keys mirror the shared pair:
`2010Q1`, `2011Q1` and `2011Q2` are in both, `2010Q2` is in `DS_1` only and `2010Q3` in `DS_2`
only.

| Id_1 | DS_1 Me_1 | DS_2 Me_2 |
|---|---|---|
| 2010Q1 | 10 | 1 |
| 2010Q2 | 20 | |
| 2010Q3 | | 2 |
| 2011Q1 | 30 | 3 |
| 2011Q2 | 40 | 4 |

The join key is `Id_1`; the left join keeps the four quarters of `DS_1`, with `Me_2` null at `2010Q2`.

"**aggr** aggregates values of non-identifier components ... The role of the components can be specified, so the original role can be changed if the name is kept the same; if the role is not specified, it will be **measure**. All non-identifier components are removed, and only the components generated by the sub-expressions are kept". The User Manual: in aggregations "the input Data Points having a **null** value are in general not considered". Aggregate invocation: **group all** "converts the values of an Identifier Component using *conversionExpr* and keeps all the resulting Identifiers" (the option is marked "(*) This option is deprecated"). Time aggregation: "On *time_period* type, the operator maps the input value into the comprising larger time period specified by the *periodIndTo* parameter", and with an aggregation "the source dataset must have exactly one Identifier of type time, date or time_period". The manual's own example is `sum ( DS_1 group all time_agg ( "A" ))`, which turns `2010Q1` into `2010`. The result keeps `Id_1`, converted to years: 2010 groups `Me_1` {10, 20}; 2011 groups {30, 40}.

| Id_1 | Me_3 |
|---|---|
| 2010 | 30 |
| 2011 | 70 |
