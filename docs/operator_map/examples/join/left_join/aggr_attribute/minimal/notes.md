# left_join: aggr_attribute

Authored. The `aggr` clause sums `Me_1` by `Id_1` into the measure `Me_3` and takes the largest `Me_1` into `At_1`, with the role `attribute`, as in the page's syntax example `aggr Me1 := sum(Me1), attribute At20 := avg(Me2) group by Id1, Id2`.

Manual page: [Left Join](https://sdmx-twg.github.io/vtl/v2.2/reference_manual/operators/Join%20operators/Left%20Join/index.html).

Inputs (shared by the `inner_join`, `left_join` and `full_join` minimal examples): `DS_1` and
`DS_2` have the same identifiers `Id_1` (Integer) and `Id_2` (String) and one Number measure each,
`Me_1` and `Me_2`, so no component other than the identifiers is in both. The keys `(1,A)`,
`(2,A)` and `(2,B)` are in both; `(1,B)` is in `DS_1` only and `(1,C)` in `DS_2` only.

| Id_1 | Id_2 | DS_1 Me_1 | DS_2 Me_2 |
|---|---|---|---|
| 1 | A | 10 | 1 |
| 1 | B | 20 | |
| 1 | C | | 2 |
| 2 | A | 30 | 3 |
| 2 | B | 40 | 4 |

`DS_2` has the same identifiers as `DS_1`, so the join keys are `Id_1`, `Id_2` and "the `using` clause is optional". The data points are matched "according to SQL left-outer join": every data point of `DS_1` is kept, and "Measures coming from that data set take the null value of their respective domains" when its key is not in `DS_2`. VDS₁ holds `(1,A)`, `(1,B)` (with `Me_2` null), `(2,A)`, `(2,B)`.

"**aggr** aggregates values of non-identifier components ... The role of the components can be specified, so the original role can be changed if the name is kept the same; if the role is not specified, it will be **measure**. All non-identifier components are removed, and only the components generated by the sub-expressions are kept". The User Manual: in aggregations "the input Data Points having a **null** value are in general not considered". `At_1` has the role Attribute; it is a Number, like `max(Me_1)`. `Id_1` = 1 groups `Me_1` {10, 20}, `Id_1` = 2 groups {30, 40}.

| Id_1 | Me_3 | At_1 |
|---|---|---|
| 1 | 30 | 20 |
| 2 | 70 | 40 |
