# cross_join: aggr_attribute

Authored. The `aggr` clause sums `Me_1` by `Id_1` into the measure `Me_3` and takes the largest `Me_1` into `At_1`, with the role `attribute`, as in the page's syntax example `aggr Me1 := sum(Me1), attribute At20 := avg(Me2) group by Id1, Id2`.

Manual page: [Cross Join](https://sdmx-twg.github.io/vtl/v2.2/reference_manual/operators/Join%20operators/Cross%20Join/index.html).

Inputs (shared by the `cross_join` minimal examples): `DS_1` has the identifier `Id_1`
(Integer) and the measure `Me_1`; `DS_2` has the identifier `Id_2` (String) and the measure
`Me_2`. No component is in both operands, so the cartesian product needs no alias to be valid.

| DS_1 Id_1 | DS_1 Me_1 |   | DS_2 Id_2 | DS_2 Me_2 |
|---|---|---|---|---|
| 1 | 10 | | A | 1 |
| 2 | 20 | | B | 2 |

The operator performs "a *cartesian product* of the input operands", and "the final result has a size equal to the product of the sizes of each input data set": 2 x 2 = 4 data points, each component appearing once with its name and role.

"**aggr** aggregates values of non-identifier components ... The role of the components can be specified, so the original role can be changed if the name is kept the same; if the role is not specified, it will be **measure**. All non-identifier components are removed, and only the components generated by the sub-expressions are kept". The User Manual: in aggregations "the input Data Points having a **null** value are in general not considered". `At_1` has the role Attribute; it is a Number, like `max(Me_1)`. `Id_1` = 1 groups `Me_1` {10, 10}, `Id_1` = 2 groups {20, 20}.

| Id_1 | Me_3 | At_1 |
|---|---|---|
| 1 | 20 | 10 |
| 2 | 40 | 20 |
