# cross_join: aggr_group_all

Authored. The `aggr` clause sums `Me_1` with the deprecated `group all time_agg("A")`, which groups the quarters by year.

Manual page: [Cross Join](https://sdmx-twg.github.io/vtl/v2.2/reference_manual/operators/Join%20operators/Cross%20Join/index.html).

Inputs (own pair: `group all` needs a time identifier): `DS_1` has the identifier `Id_1`
(Time_Period, quarters) and the measure `Me_1`: (2010Q1, 10), (2010Q2, 20), (2011Q1, 40).
`DS_2` is the cross pair's: `Id_2` (String) and `Me_2`: (A, 1), (B, 2). No component is in both.

The cartesian product has 3 x 2 = 6 data points.

"**aggr** aggregates values of non-identifier components ... The role of the components can be specified, so the original role can be changed if the name is kept the same; if the role is not specified, it will be **measure**. All non-identifier components are removed, and only the components generated by the sub-expressions are kept". Aggregate invocation: **group all** "converts the values of an Identifier Component using *conversionExpr* and keeps all the resulting Identifiers" (the option is marked "(*) This option is deprecated"). Time aggregation: "On *time_period* type, the operator maps the input value into the comprising larger time period specified by the *periodIndTo* parameter", and with an aggregation "the source dataset must have exactly one Identifier of type time, date or time_period". Example 1 of the Time aggregation page is `sum ( DS_1 group all time_agg ( "A" ))`, which turns `2010Q1` into `2010`. The result keeps `Id_1` (converted to years) and `Id_2`: (2010, A) and (2010, B) each group `Me_1` {10, 20}; (2011, A) and (2011, B) each group {40}.
