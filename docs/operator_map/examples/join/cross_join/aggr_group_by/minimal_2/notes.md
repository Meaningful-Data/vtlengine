# cross_join: aggr_group_by (minimal_2)

Authored. The `aggr` clause takes the largest `At_1`, an Attribute of `DS_1`, by `Id_1`, under its own name and with the role left out.

Inputs: `DS_1` has the identifier `Id_1`, the measure `Me_1` and the **Attribute** `At_1`: (1, 10,
a), (2, 20, b); `DS_2` has the identifier `Id_2` and the measure `Me_2`: (A, 1), (B, 2). The
cartesian product has 4 data points, and VDS₁ keeps `At_1` ("The components coming from exactly
one input data set, which appear once and maintain their original name and role").

The join page: "**aggr** aggregates values of non-identifier components by indipendent sub-expressions evaluated at component level. The role of the components can be specified, so the original role can be changed if the name is kept the same; if the role is not specified, it will be **measure**. All non-identifier components are removed, and only the components generated by the sub-expressions are kept". So `At_1` is a Measure in the result. Outside a join, the Aggregation clause page gives the opposite default: "if the component exists in the operand Data Set then it maintains its role". With **group by** the identifiers not named are dropped. `max` on a String gives a String (Maximum value: "For other comparable scalar types (for example **time**, **string**, **boolean**), the result has the same type as the operand"). `Id_1` = 1 groups `At_1` {a, a} and `Id_1` = 2 groups {b, b}.

| Id_1 | At_1 |
|---|---|
| 1 | a |
| 2 | b |
