:Tests: the default window when the order key is a String, ``Id_3``: ``x`` on three data points of ``A`` and ``y`` on the fourth.
:Manual: `Analytic invocation <https://sdmx-twg.github.io/vtl/v2.2/reference_manual/operators/Aggregate%20and%20Analytic%20operators/Analytic%20invocation/index.html>`__: range "cannot be used for components having the following Data Types: String, Duration and TimeInterval Point", but the default "range between unbounded preceding and current data point" has no offset to compute on the values of the key. It is read as applying whatever the type of the key, as in SQL.
:Expected: in ``A``, the three data points at ``x`` (1, 3 and 4) tie, so ``Me_2`` is 8 on each, and 8 + 2 = 10 at ``y``; in ``B`` (5 and 6, both at ``x``), 11 on both.
:Finding: both engines give the whole partition, 10 in ``A`` and 11 in ``B`` (`#1249 <https://github.com/Meaningful-Data/vtlengine/issues/1249>`__). An explicit range window on a String key raises ``1-1-19-13`` on both.
