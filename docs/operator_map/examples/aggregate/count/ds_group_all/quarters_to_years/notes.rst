:Tests: ``count`` with the deprecated ``group all time_agg ( "A" )``, which turns each quarter of ``Id_2`` into its year, written ``2020`` or ``2021``.
:Manual: `Aggregate invocation <https://sdmx-twg.github.io/vtl/v2.2/reference_manual/operators/Aggregate%20and%20Analytic%20operators/Aggregate%20invocation/index.html>`__: "group all: converts the values of an Identifier Component using conversionExpr and keeps all the resulting Identifiers"; ``time_agg``: "On time_period type, the operator maps the input value into the comprising larger time period specified by the periodIndTo parameter".
:Expected: ``Id_1``, the year and ``int_var`` = 2 for ``A, 2020``, ``A, 2021`` and ``B, 2020``.
:Team decision: `#1049 <https://github.com/Meaningful-Data/vtlengine/issues/1049>`__: over a data set, ``count`` gives one Integer measure ``int_var`` whatever the measures of the operand, and ignores the data points whose measures are all null. With two measures, this settles the conflict between the count page's ``int_var`` and the Aggregate invocation's "the resulting Data Set has the same Measures as the operand".
