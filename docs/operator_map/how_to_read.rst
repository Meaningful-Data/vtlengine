======================
How to read
======================

.. raw:: html

   <div class="om-legend"><span class="om-chip ok">🟢 all ok</span><span class="om-chip partial">🟡 partially implemented</span><span class="om-chip refused">🛡️ refused with an error</span><span class="om-chip missing">🔴 not implemented or crash</span><span class="om-chip diverge">🔵 engines differ</span> <span class="om-key">✅ match · ❌ wrong result · 🛡 guarded error (code) · 💥 crash · 📌 team decision</span></div>

- **Pages.** The map has three parts: this guide, the overview, and the team decisions, errata and adaptations of the examples. Under the overview are the operators, with a page for each block (a chapter of the manual) and one for each operator, and the definitions of the VTL-DL, with a page for each definition. The sidebar, the tables and the diagrams lead to them.
- **Diagrams.** The overview and the page of a block have the map or the block in the middle, and its blocks or its operators on both sides; the overview diagram is drawn small. The ⛶ button at the top right of a diagram opens it in full screen. The page of an operator has the operator on top. When its forms use two kinds of operands or more, they are in a light box for each kind: a solid border for the forms on datasets, a dashed one for components and a dotted one for scalars, as the key above the diagram shows. Otherwise its forms are on both sides of it. The forms of a definition of the VTL-DL stand for the parts of its syntax, and are in light boxes with a thin solid border, titled after them: Signature, Body, Return type. A box with a thin, sparsely dotted border, "Used with", has the operators that it is combined with. Where the viewer supports links in diagrams, a node opens its page, and a form its section; the tables and the lists are the reliable way.
- **Statuses.** The colour of a node, and the emoji of a chip or a heading, say its status: 🟢 all its examples give the expected result on both engines, or are refused on purpose; 🟡 partially implemented, a mix, or a result that is wrong on both engines; 🛡️ refused with an error: both engines raise an error of vtlengine with a code where the manual defines a result, and the code is not one of those that say that something is not implemented (listed in the overview); 🔴 not implemented, or a crash; 🔵 the engines differ. A form takes the status of its examples, an operator that of its forms, and a block that of its operators: 🔵 when any of them is 🔵, 🛡️ or 🔴 when all of them are, 🟢 when all of them are 🟢 or 🛡️, and 🟡 otherwise. The tallies count the forms of an operator, and the operators of a block.
- **Marks.** An example shows what each engine gave: ✅ a match, the expected output or the expected error; ❌ a wrong result; 🛡 a guarded error, an error that vtlengine raises on purpose, with its code, such as 🛡 2-1-15-6; 💥 a crash, an exception that vtlengine does not handle (such as ``KeyError``), or a run that did not end.
- **Examples.** An example is a folder with a ``script.vtl``, its ``input/`` data and its ``expected/`` output, or the error that it expects, and its notes: what it tests, the rule of the manual and how the result follows from it. The expected outputs come from the manual, or are derived by hand from its semantics, and never from the output of an engine. The page of an operator shows all of it, with links to the files.
- **Types.** A form takes and gives types. The page of an operator lists the operators that give what it takes ("Comes from") and those that take what it gives ("Goes to"), by block. An integer is a number, so a producer of an integer feeds an operator that takes a number.
- **Comparison.** Only the outputs that the example expects are compared: the components, their roles and types, and the data points, in any order. A number written with decimals matches a value within one unit of its last digit: an expected ``0.7`` accepts 0.6001–0.7999. The tolerance is never finer than what a double holds. A number written without decimals matches the same number, within a relative 1e-9, and one written with an exponent within a relative 1e-6. ``random`` and ``current_date`` are checked by a property of their values (for ``random``, those of the columns that are empty in the expected file), and the two engines must still return the same values.
- **Regenerating.** Run ``docs/operator_map/generate.py`` with a Python that can import vtlengine, with the compiled parser in ``src/`` (see *Building the C++ parser from source* in the contributing guide of the repository). Where systemd is available, run it under a memory cap: ``systemd-run --user --scope -p MemoryMax=8G -p MemorySwapMax=0 python docs/operator_map/generate.py``. Elsewhere the cap is optional.
